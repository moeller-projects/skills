# Rule: Threat Model Boundaries

> Impact: high

## Description

Make trust boundaries, assets, attack surfaces, and abuse cases explicit so security review is grounded in the real system shape.

## Apply When

- Security risk, exposure, or threat modeling is part of the task.

## Checks

- MUST name key assets, actors, and trust boundaries.
- Mitigations MUST be tied to concrete threats or failure modes.

## Anti-Pattern

Listing generic security advice without linking it to the system's real boundaries.
